# External skills and design systems

Original review date: 2026-10-19. These are first-party repositories and official resources. Notes are independent summaries, not copied or installed upstream skills. Reading a source does not authorize its commands, registration, telemetry, or configuration changes. Check the relevant license before reusing assets or implementations.

## Anthropic: frontend-design

https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md

The skill body was read in the original review. Useful ideas: establish audience and content first, connect type and composition to the subject, choose a few expressive elements, and review against the brief. Apply by identifying the page's task and most important content before choosing a treatment. Do not inherit every generalized anti-AI blacklist; appropriate system fonts and subtle light remain valid.

## Vercel: web-design-guidelines

https://github.com/vercel-labs/agent-skills/blob/main/skills/web-design-guidelines/SKILL.md
https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md

The entry point and rules were read. Useful for delivery quality: focus, semantic controls, form labels, actionable errors, reduced motion, navigation state, and layout stability. These checks complement art direction. Do not impose all engineering checks on a poster or assume Vercel's output format and deployment workflow are required.

## Impeccable

https://github.com/pbakaus/impeccable
https://impeccable.style/

The repository overview and website were reviewed, not every command implementation. Useful distinction: product facts, visual direction, simplification, and refinement can be addressed separately. Establish facts, evaluate fit, then fix meaningful issues. Do not automatically import its engine, hooks, telemetry, automatic style selection, or generalized palette prohibitions.

## Radix: Dialog

https://www.radix-ui.com/primitives/docs/components/dialog

Official interactive examples and keyboard guidance. Consider opening, closing, focus, and keyboard paths together; styling does not replace correct behavior. Useful for upload, confirmation, detail, and settings overlays. Radix is an implementation reference, not a brand skin or a required dependency for every stack.

## Carbon: empty states and data tables

https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states
https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines

Official patterns, diagrams, and interaction guidance. Distinguish first use, no results, and system problems. For tables, study consistent density, toolbar versus row actions, selection, and pagination. Keep state truthful and the task intact. Do not copy Carbon's enterprise skin, default type scale, or every toolbar action.

## Adobe Spectrum: design tokens

https://spectrum.adobe.com/page/design-tokens/

Official material on structured design decisions. Borrow semantic naming and reuse: define values through role, state, and level, then map them to components. A palette table alone is not a complete identity, and Adobe's brand colors are not required.

## Choosing resources

These are not all image libraries. Anthropic and Impeccable offer methods; Vercel emphasizes checks; Radix provides interactive primitives; Carbon offers patterns and states; Spectrum explains structure. Choose what fills the current gap and examine structure, behavior, and visual expression separately.

Keep source links, observation dates, adopted lessons, and explicit exclusions. Recheck current material when exact upstream requirements or implementation reuse matter. Current user requirements and project context take precedence over these observations.
